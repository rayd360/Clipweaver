# ClipWeaver Editor

Create three distinct edits of the user's own footage, delivered as one downloadable package_version 2 `.clipweaveredit` response with shared graphics embedded that ClipWeaver can render locally. Use this workflow for ClipWeaver packages containing `manifest.json`, 8 fps review videos, separate audio, and timestamped storyboards.

Read [references/edit-format.md](references/edit-format.md) before writing the edit. In a flattened upload package, this is also provided as `EDIT-FORMAT.md`. The format is an executable contract: use only supported operations. Read the manifest, then inspect actual media with available tools.

## Understand and inspect

Use the user's existing idea, target length and mood. Keep source shape and use the music selection in the manifest; do not ask about shape or music. Choose reasonable creative details yourself; ask only about missing information that materially changes the edit. A request may intentionally combine different moments from the same original, rearrange chronology, or reuse a shot.

Uploading or opening an MP4 is not proof of audiovisual understanding. Establish which tools in this session can decode/display frames, inspect motion, listen to audio, or transcribe speech. If direct video analysis is unavailable, use storyboards for discovery and extract denser frames from review videos around candidates when a tool can do so. If audio tools are unavailable, disclose that gap and obtain the needed transcript or listening support before relying on speech, beat timing, or sonic events. Never invent dialogue or describe an unseen moment as observed. A transcript cannot establish music or ambient sound.

Review copies play at the original speed. All times refer to original-source elapsed seconds, starting at the first displayed video frame. `review_time_offset` maps any future split excerpts back to that timeline. Use manifest durations; do not infer source frame numbers from 8 fps copies. Storyboards are sampled approximately every two seconds and can miss events. The review video is sampled every 0.125 seconds, so very precise cuts can still require confirmation against originals in the local preview.

Keep a compact evidence list: source ID, time range, observed action, usable sound, and relevance to the idea. Inspect all supplied sources that could reasonably matter. For large packages, work in batches, retaining IDs and observed ranges. Ask for a focused excerpt at a named source/time when visual detail is insufficient.

## Selected style reference and global branding

When manifest.style_reference exists, inspect its named video in reference/ at its original frame cadence. This is the user's selected video to mock: study shot lengths, build-up, framing, caption hierarchy, individual word entrances, transitions, and ending. Translate these observations into supported ClipWeaver operations using only manifest.sources. The reference is not a source clip and must not appear in clips or embedded response assets. Do not copy its wording, footage, logo or branding. Use the user's global logo supplied as manifest.project_logo when requested. If a reference effect is unsupported, approximate with available fields and state the limitation. User idea, target duration and explicit instructions take priority over the reference. Disclose inability to inspect reference motion or hear audio; do not claim a close match without observation. When no style_reference exists, do not invent a reference.

When manifest.sources contains a COMBINED_ source, it is the lossless full-quality master. Select multiple ranges from its long timeline, using combined_parts to locate original events. All clip start/end values must be on the master timeline, not the individual original timeline. Never use IDs found only in combined_parts as editable source IDs. Do not ask the user to upload constituent originals when the combined review is sufficient. Reference videos remain separate and are never editable source IDs.

## Make the edit

Choose an opening, progression, and ending appropriate to the idea. Prioritize useful content, pacing, and clear speech. Select multiple noncontiguous sections of the same source whenever they improve the video. Avoid cutting off important words. Keep narration and unrelated background sound distinct in your decisions.

Use `fps: "source"` by default. ClipWeaver then uses the original frame rate of the first selected source, for social and website exports alike. Never request 8 fps for the final video. For mixed source rates, explain the chosen timeline rate if setting it explicitly. Leave compression choices to the Mac app. It renders from original footage, never from review copies.

Always use `aspect: "source"` and `fps: "source"`. Fit framing preserves the whole shot. All three choices serve the same brief and reference style but differ meaningfully in opening, source moments, sequencing, narrative and caption wording. Do not produce three renamed duplicates or merely change colors. Give each a distinct descriptive title and a short explanation in notes. Keep any requested duration range for each version. Social and Website are export-quality choices, not separate creative versions.

For new edits use schema_version 4 and choose one transition_style for the entire video: cut, or cross_dissolve. For cut, every transition is 0. For cross_dissolve, AI chooses 0.5–0.8 seconds on every clip after the first; the first is always 0. Never mix normal cuts with dissolves. An end_card must use the same style via its transition field (0 for cuts, 0.5–0.8 for dissolves). Account for overlap in total duration. Source audio is retained at volume 1 unless the plan changes it. Clip volume 0 mutes that selection. Use schema_version 4 captions for word-level promotional wording or verified subtitles, and end_card for a branded static ending. Ordinary words are white; emphasized words are larger, bold italic charcoal. Design editorial captions as compact phrases of 2–6 words, with one or two large focal words. Prefer normal font_size 0.045–0.06 and emphasis_scale 1.3–1.6, checking line lengths. Avoid tiny captions or excessive empty space. Ordinary lettering is solid white and emphasis is heavier italic. Use charcoal with contrast_backing true over busy/dark footage, or #E8E9EC with contrast_backing false for clean luminous emphasis. Charcoal without backing is for backgrounds with sufficient light contrast. Use deliberate 1–3 line compositions and stagger words 0.12–0.25 seconds apart with 0.2–0.4 second slide entrances; hold completed phrases long enough to read. Do not make every word the same size or animate mechanically. Inspect actual output frames when available, including motion before settling, and revise typography/layout if it is small, crowded, low-contrast or lifeless. Reuse caption_styles with per-word overrides. Use words entries for single words or short styled segments; do not create per-frame images or font files. Inspect manifest.project_logo and its image when present; use logo_placements only when the user requested that project logo. Never borrow branding or wording from a style reference. Keep static overlays available for older edits and supplied graphics. Overlay times are finished-video seconds; clip cuts remain original-source seconds. Avoid unsupported speed changes or arbitrary effects. Keep wording brief, readable, and inside social safe areas. Do not invent dialogue or business branding.

## User-selected music

Never generate or compose music, and never embed audio in new responses. If manifest.selected_music exists, inspect its listening file to plan pacing; its start is the user's selected song offset, and the app loops the track as needed. Omit `music` in every edit: the app applies the user's selection and start locally. With no selection, use appropriate original audio without inventing a soundtrack. Mute distracting source sound when a selected track should lead. Disclose if you cannot hear the track rather than claiming beat synchronization.

## Validate and deliver

Use the exact project ID and source IDs from `manifest.json`. Include original filenames in the readable summary so the user can recognize selections. Check bounds, durations, frame rate, crop settings, music references, and crossfade overlaps. If code execution is available, run `scripts/validate_edit.py choices.json manifest.json`; it uses only Python's standard library. Otherwise check the same constraints explicitly.

Deliver one `.clipweaveredit` response. Save a JSON array of exactly three valid EditPlan objects in choices.json. Run `scripts/pack_response.py choices.json manifest.json asset_directory output.clipweaveredit` to validate and embed all referenced assets. Keep separate internal edit/graphics files in the working project folder; the user should only need the final response. If the user's prompt supplies a local Incoming folder and tools have access, save the response atomically there; the app detects it automatically. Otherwise return the single downloadable file for double-clicking. Do not claim automatic delivery unless the file was actually saved there.

Include a short sequence summary, runtime, frame rate, sound choices, and any inspection uncertainty. The user can preview and export Social or Website without locating music or graphics separately. For revisions, preserve project/source identities and return a new response; the app keeps earlier edits. Reuse accessible media without requesting duplicate uploads.


### Original-video boundaries in a combined master

`combined_parts` records the exact start and end of every original in the long master. Never let a single clip selection cross an internal boundary. The app and validator reject it. Choose separate selections explicitly if both originals should appear. For three ten-second originals, 8–11 is invalid; use 8–10 and 10–11 as two selections. Apply the edit's uniform transition rule between them and account for overlap; for dissolves, lengthen selections if necessary to leave room for the required 0.5–0.8 seconds. Do not infer boundaries from visual changes; use the manifest's exact times.

Caption font sizes are desired sizes: ClipWeaver wraps styled phrases and uniformly shrinks a caption group to fit the source shape. Emphasis ratios, wording and timing stay intact. Still favor concise phrases and generous boxes so automatic fitting does not make the text too small.


## Current workflow: face-safe captions, brands and revisions

Read the root manifest first; it overrides any preserved older manifests/instructions inside original-review. Use manifest.brand.name exactly for brand wording when needed. The initial brand is Rhythm & Flash Events; do not assume all future projects use it, and never borrow source-event or reference branding.

If captions_enabled is false, omit captions, caption_styles, and static text or image caption overlays in all three edits. Do not bake captions into PNG assets. The local checkbox also suppresses added captions and static overlays after import; it does not remove words already recorded in the original footage, the separate logo, or an end card.

When captions are enabled, they remain optional. Before placing each word group, inspect every visible interval, including entrances, moving heads, and both clips during dissolves. No added word or caption may cover any person's face at any time. Avoid existing source lettering unless overlapping it is the best readable placement; this exception NEVER applies to faces. Choose another location, change the caption timing, shorten the text, or omit it. If the available tools cannot establish a face-free area throughout the interval, omit the caption and disclose the inspection limitation. Do not claim a face-safety check based on a single storyboard frame. Preserve face clearance when selecting sizes, line breaks and slide paths, allowing room for local auto-fitting.

Choose each alternative's runtime, pacing and caption timing independently from the actual content and narrative. Do not copy a fixed duration or caption timetable across all three versions. Honor a user's explicit duration or range; do not force different runtimes just for cosmetic variation when an exact duration was requested. Different openings, moments, rhythm and messages should make the alternatives meaningfully distinct.

When revision.json exists, this is a revision request. Read its selected choice/title and requested_changes. Inspect selected-output.mp4 (the entire selected finished video at source frame rate), selected-edit.json (original AI instructions), rendered-edit.json (effective local caption/music settings), the previous-response.clipweaveredit if present, and original-review materials. Revise ONLY the selected edit as the baseline, returning three new interpretations of the requested changes. Preserve aspects not requested to change. Times in the user's change notes refer to the selected finished output; map them back through source selections and transition overlaps. All new clips still use original-source/master seconds, never finished-output seconds as source cuts. Root manifest settings, current brand/music and caption preference take priority over old response settings. Validate/pack against the root manifest.json, not the preserved old manifest. Deliver the usual one package_version 2 response with exactly three edits.
